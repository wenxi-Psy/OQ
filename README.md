# OQ-45.2 在线填写与结果呈现

心理咨询效果问卷（Outcome Questionnaire, OQ-45.2）中文版的网页版填写与计分工具。
纯静态页面，无后端、无构建步骤、无第三方依赖，部署在 GitHub Pages。

**页面地址**：<https://wenxi-psy.github.io/OQ/>

**量表版本**：秦佑凤、胡姝婧（2008）中文译本，全 45 题。

1. 打开仓库 **Settings → Pages**

   目录选 `/ (root)`

### 改完 assets/ 记得改缓存版本号

`index.html` 里对 `assets/` 的每个引用都带一个 `?v=20260903a`：

```html
<link rel="stylesheet" href="assets/style.css?v=20260903a">
<script src="assets/app.js?v=20260903a"></script>
```

GitHub Pages 给静态资源发的是 `Cache-Control: max-age=600`。只改文件内容的话，
**已经打开过页面的浏览器在十分钟内仍然用缓存里的旧 JS**，新页面配旧脚本，
表现是"改动看起来没生效"——真实踩过一次：代码已经合并上线，导出的 CSV 还是上一版的格式。

改完 `assets/` 下任何文件，把 `index.html` 里的 `v` 一起改掉（日期 + 当天序号即可），
浏览器就会当成新地址重新取。

## 实现要点

### 计分

- 五点计分 0–4，分数越高困扰越重。
- **9 道反向题**（1, 12, 13, 20, 21, 24, 31, 37, 43）在 `score.js` 中**只反转一次**。
  导出时把反向前后的值分列给出（`response_raw` / `scored`），计分算式逐行写在旁边，避免录入时二次反转。
- 三个维度：症状困扰 SD（25 题，0–100）、人际关系 IR（11 题，0–44）、社会角色 SR（9 题，0–36）；
  总分 0–180。

### 「不适用」的统一处理

有 6 道题可能对某位来访者根本不成立：**7、17、37**（恋爱/性关系）与 **11、26、32**（酒精/药物）。

纸质题本的做法是逐题印一句「如不适用请填 X」，而 **X 随计分方向不同**：

| | 计分方向 | 题本上应勾 | 原始值 | 反向计分后 |
|---|---|---|---|---|
| 7, 17, 11, 26, 32 | 正向 | 不是 | 0 | 0 |
| **37** | **反向** | **总是这样** | **4** | **0** |

两种写法的落点是同一个：**0 分困扰**。差别只是因为第 37 题是反向题——没有恋爱关系的人若照
其他题的直觉勾"不是"，反转后会变成 4 分（最高困扰），凭空多出 4 分。

让作答者自己判断哪几道题是反向题是不合理的，所以页面**统一给这 6 道题各配一个「不适用」按钮**，
由 `score.js` 按计分方向换算，作答者不需要知道反向题的存在：

- 页面内部记为 `'na'`，`oqScore()` 一律记 0 分困扰
- 导出时 `oqPaperValue()` 换算回题本等价值（正向题 0，反向题 4），便于与纸笔施测数据对齐
- 导出里「不适用」单独占一列（`not_applicable`），不与"答了 0 分"混在一起
- 「不适用」不触发关键题跟进（不喝酒的人不会因第 11、26、32 题被标记）

按钮文字逐题写具体（如「不适用：目前没有恋爱关系」「不适用：我不喝酒」），
并在填答页开头说明**只有情况确实不存在时才选**，避免被当成"跳过"用。

> 这样改**不改变任何分数**：正向题选「不适用」与选「不是」同为 0 分，第 37 题的处理与题本一致。
> 因此 62/17 的常模可比性不受影响。

### 漏答处理

| 情况 | 处理 |
|---|---|
| 漏答 1–4 题 | 用该题所属**分量表**其余题目的均值（四舍五入取整）填补，结果页明确列出哪几题是估算值 |
| 漏答 ≥ 5 题 | 拒绝出分，提示补答（对应"完成 ≥ 41 题"的门槛） |

### 常模

| 指标 | 数值 | 出处 |
|---|---|---|
| 总分划界分 | **62** | 李钰静 (2010) 中国常模 |
| 总分可信变化指数 RCI | **17** | 李钰静 (2010) 中国常模 |
| 严重度分层 | < 64 低｜64–82 中度｜83–105 中高｜> 105 高 | 美国常模 |
| 分量表划界分 | SD 37｜IR 16｜SR 13 | 美国常模 |

两点在页面上有显式标注：

1. **62 的划界分与 64 起点的严重度分层出处不同**，页面分开呈现，不混用。
2. **62/17 建立在李钰静译本上**，本页面用的是秦佑凤、胡姝婧译本。两译本条目内容高度一致、
   维度归属完全相同，沿用属合理外推，但记录时应注明。中国的分量表划界分与 RCI 未见公开发表，
   页面上的分量表参考线取自美国常模。

分量表分在页面上明确标注为**定性线索**，不作疗效指标——中文版分量表 α 低至 0.57
（秦佑凤、胡姝婧, 2008），不足以支撑单独下结论。

### 变化判定（Jacobson-Truax）

Δ = 基线分 − 当前分（正值表示好转），用中国常模 RCI = 17、划界分 = 62：

| 判定 | 条件 |
|---|---|
| 恢复 | Δ ≥ 17 且 当前分 < 62 |
| 改善 | Δ ≥ 17 但 当前分 ≥ 62 |
| 无变化 | \|Δ\| < 17 |
| 恶化 | Δ ≤ −17 |

页面默认与**上一次**记录比较；若存在被标记为"基线"的记录且不是上一次，会额外给出与基线的比较。

### 两张变化折线图

记录满 2 次后，结果页给出两张图（网页和导出的长图里都有）：

| 图 | 纵轴 | 参考线 |
|---|---|---|
| 总分变化 | 0–180 原始分 | 划界分 62（中国常模） |
| 三个维度的变化 | **各维度占自己满分的百分比** | 36.5% |

维度图必须做归一化：三个维度满分不同（SD 100 / IR 44 / SR 36），画在同一根原始分纵轴上，
IR 和 SR 会被压在下半部分，看不出各自的变化。

换算成百分比之后有个好用的巧合——**三条美国常模划界分几乎重合**：

```
SD  37 / 100 = 37.0%
IR  16 /  44 = 36.4%
SR  13 /  36 = 36.1%
```

差异不到 1 个百分点（在 172px 高的绘图区里不到 2px），所以**一条虚线就能同时代表三个维度的参考线**。

其他实现细节：

- 三条线除颜色不同外**线型也不同**（实线 / 虚线 / 点线），色觉障碍者靠线型即可区分
- 不在线末标数值——三条线收尾时常挨在一起，标签会叠成一团；本次原始分由图例给出，
  网页版每个圆点还有 `<title>`，长按/悬停可看该次的原始分
- 两张图都**铺满容器宽度、不横向滚动**。早先按最小间距展开靠滚动，结果最新一次默认在屏幕外，
  而那正是最该看到的。点多时改为抽稀日期标签（`dense`），并同样只画最近 10 次
- 旧记录或缺 `dims` 字段的记录会被过滤掉，**有效记录不足 2 条时整张维度图隐藏**

### 关键题跟进

第 **8** 题（自杀意念）**只要不为 0** 即列出；第 **11、26、32、44** 题达到"有时"（≥2）时列出。

第 8 题不为 0 时，结果页顶部会出现一段措辞克制的提示，并附 24 小时心理援助热线
（全国 12356、希望 24 热线 400-161-9995、北京心理危机干预热线 010-82951332）。

## 隐私

**作答数据不会离开浏览器**，页面不发起任何网络请求，也没有任何统计或追踪代码。

每次结果会自动保存到 `localStorage`（键名 `oq45_records_v1`），用于生成变化趋势。
说明页和结果页都提供「清除本机记录」按钮，说明页显示当前已保存的记录数。
共用设备的使用场景在页面上有明确提示。

### 匿名编号

另有一个键 `oq45_uid_v1`，存一串首次打开页面时随机生成的字符（形如 `oq-3f7a…`，
8 字节随机数走 `crypto.getRandomValues()`）。它**不含任何个人信息、不上传**，
作用只有一个：**把同一个人的多次填写可靠地串起来**。

原先只有一个「编号或昵称」输入框，可以留空、也可能每次写得不一样，靠它做纵向对齐并不可靠。
两者并存，各管各的：

| | 谁填 | 用途 | 会不会变 |
|---|---|---|---|
| 匿名编号 `user_id` | 页面自动生成 | 机器对齐同一个人的多份数据 | 除非换设备或手动改，否则不变 |
| 编号或昵称 `label` | 来访者自填，可留空 | 人看的标签 | 每次都可能不同 |

这串编号**默认是折叠的**，收在说明页「关于你的数据」卡片下的一行小字里
（「换手机或换浏览器时，怎么让记录接上」），展开后才显示编号本身和「复制」「填入旧设备的编号」
两个操作——**换设备时把旧编号抄过去，两台设备导出的数据就能对上**（本机的历史记录仍然不会
跟着走，那需要跨设备存储）。手动填入的编号限制为字母、数字、`-`、`_`，4–64 位。
无痕模式下写不进 `localStorage`，此时编号只在本次会话有效，导出文件里会标 `user_id_persistent: false`。

> 折叠是有意的：来访者的任务是填完 45 题看结果，一串 `oq-3f7a…` 摊在说明页上对他是纯噪音。
> 只有换设备这一个场景需要它，那就只在那个场景下才展开。

### 记录跟着浏览器走

`localStorage` 是**按「浏览器 + 域名」隔离**的，这带来两个真实场景下的坑，页面都做了处理：

| 情况 | 表现 | 页面的处理 |
|---|---|---|
| 从微信/QQ/小红书等 App 里点开 | 记录存在该 App 的 WebView 里，换成系统浏览器就看不到，部分 App 关闭后还会清除 | UA 识别后在说明页给出提示，建议「在浏览器中打开」并固定用同一个浏览器 |
| 无痕/隐私模式 | `localStorage` 写入直接抛异常 | 实写一次探测（`storageWorks()`），命中就提示"这次结果不会被保存"，但**不影响填写和出分** |
| 换设备 / 换浏览器 | 历史记录接不上 | 结果页可直接**手动输入上次总分**，照样做 Jacobson-Truax 判定 |

App 内置浏览器的识别靠 UA 匹配，是启发式的，只用于提示，不影响任何功能。

> 曾经做过「导出全部记录 / 导入以前的记录」的文件迁移，后来移除了：来访者面对一个
> 说不清格式的文件容易出错，而**手动输入上次总分**已经覆盖了同一个需求，还更直接。
> 逐次结果的 CSV / JSON 导出保留，供咨询师自行留档。

## 排版规则

样式里的字号、间距、缩进都从 `:root` 的一组变量取值，不再手写零散数值。

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-lg` | 16px | 结论性的一句话（`h2`、判定语） |
| `--fs-body` | 15px | 卡片正文、列表项 |
| `--fs-sm` | 14px | 次要正文、次级按钮 |
| `--fs-note` | 13px | 说明性小字（`.fieldnote`） |
| `--fs-micro` | 12px | 出处、标签 |
| `--sp-1/2/3/4` | 6/12/18/24px | 纵向节奏 |
| `--indent` | 18px | 带项目符号列表的缩进 |
| `--box-pad` | 14px | 卡片内小方框的内边距 |

**保留的字号例外**（都有具体原因，不要并入刻度）：标题与大号分数；输入框 16px（小于此值
iOS Safari 聚焦时会放大页面）；题干 16px；五点选项按钮按容纳宽度定（13px / 窄屏 12px /
宽屏 14px）；图表内的 SVG 标签 10–11px；打印样式。

### 列表只有两类

```
① 带项目符号   padding-left: var(--indent)，符号落在缩进里
② 平列 .flush  padding-left: 0; list-style: none，文字与 h2、正文同一条左边缘
```

两个曾经踩过的坑，都是同一类问题——**元素默认的标记（marker）画在内容框外面**：

- `.dimdefs` 设了 `padding-left: 0` 却没关 `list-style`，圆点被甩到卡片文字左边缘之外
- `<summary>` 的系统三角把标题文字顶右约 15px，比其他卡片的 `h2` 都靠右

现在统一处理：平列一律 `list-style: none`；`<details>` 去掉系统三角，改用绝对定位的
CSS 箭头放在右侧，标题因此与其他卡片标题严格对齐。

```
      症状困扰 SD                          50                38

      较上次                               首次（基线）      −21 改善

```

- **列数** = 4 固定 + 评估次数，填 10 次也才 14 列；**行数**恒为 58，加评估只加列，表不会越变越长
- 上半张是整体结果，打开第一眼就看到总分与变化判定；下半张是逐题明细
- 时间从左到右，最新一次在最右边

**格子里放的是计分值**（已完成反向计分），所以 45 道题方向统一——数字越大困扰越重，
横着扫一行就知道这道题在变好还是变差。作答者实际勾的档位可以反推：
反向题的原始值 = 4 − 计分值，是不是反向题表里有一列。

两种特殊情况在格子里标出来，那个 0 不会和「真答了不是」混为一谈：

| 格子 | 含义 |
|---|---|
| `0 不适用` | 这题的情况对他不成立，一律记 0 分困扰 |
| `2 估算` | 漏答，按同维度其余题目的均值填补 |

上半张表另有「不适用题号」「漏答题号」两行，快速扫一眼就知道这次有没有特殊情况。

> 试过两种别的排法，都不如这个。**一次一行、逐题 45 列**：题干进不了表，看到 `q08`
> 还得另查是哪道题。**一题一行、每次重复 45 行**：填写日期会在 45 行里重复 45 遍，
> 三次评估就是 135 行，纯冗余。
>
> 更早还做过「一次填写导出一个文件」，配一张单独的 `codebook.csv` 说明每列什么意思——
> 两个文件必须成对保管，少一个就读不懂，而且历次记录散在一堆文件里对不起来。

分数每次都从逐题作答**重新算**，不直接读存下来的总分。这样早于版本号那版的旧记录
（只存了总分和维度分）也能补出逐题分、关键题和漏答标记，只有「提交时刻」「量表版本」
两行会留空。

### 版本号与本地存储

`localStorage` 里的记录按变量名存逐题作答（`answers` 字段，`q01`–`q45`），不按数组下标——
题目顺序万一调整，靠位置对齐的历史数据会整体错位，而且错得悄无声息。旧记录只有数组，
读取时按题目顺序还原一次，历史记录不会丢。

每条记录还带三个版本号和两个时间：

| 字段 | 说明 |
|---|---|
| `itemsVersion` | 条目内容的版本（题干、维度归属、反向标记、关键题、「不适用」规则），见 `assets/items.js` |
| `scoringVersion` | 计分规则的版本（反向计分、漏答填补、常模与判定阈值），见 `assets/score.js` |
| `OQ_EXPORT_SCHEMA` | 导出格式的版本，结构变了就 +1，见 `assets/export.js` |
| `startedAt` / `completedAt` | 点「开始填写」与提交的时刻，ISO 8601；导出时换成本地时间 |
| `durationSec` | 作答时长（秒）。**墙上时间**，中途去做别的事也照算，只能当粗略参考 |

三个版本号分开记，是因为它们确实会分开变：只调常模不动条目、只改导出结构不动计分，
都是会发生的事。CSV 里「量表版本」一行带的就是前两个。

> 版本号救过一次场：CSV 导出改版上线后，页面导出的仍是旧格式，靠导出文件里的
> `export_schema` 还停在上一版，三十秒就判断出是浏览器缓存而不是代码没合并。

### 为什么加「保存为图片」

`window.print()` 在移动端不可靠：iOS Safari 只给 AirPrint，「存储到文件」藏得很深；
**App 内置浏览器里往往完全没反应**。而手机用户真正需要的是一张能存进相册、能直接发出去的图。

结果图用 **canvas 手绘**（`drawCard()`），不引第三方库——中文由系统字体渲染，
不需要嵌入字体文件（嵌一套中文字体要 5–10 MB）。实现要点：

- 两遍绘制：先在临时 canvas 上量出内容总高度，再按真实尺寸重画，高度随内容自适应
- 输出 2 倍像素（逻辑 640px → 1280px）
- 图片内容：总分与刻度、三维度、与上次比、**总分变化折线图**、**三维度变化折线图**、关键题、免责声明
- 折线图最多画最近 10 次（再多横轴日期会挤成一团），超出时在图上注明总次数
- 图片固定用浅色配色，便于打印和在深色聊天界面里查看

保存分两条路，覆盖不同平台：

| 方式 | 适用 | 实现 |
|---|---|---|
| 长按图片 | 手机 | `<img>` 用 **data URL**——iOS 上长按 blob URL 的图片存相册经常失败 |
| 「保存 / 分享图片」按钮 | 全平台 | 优先 `navigator.share({files})` 调起系统分享面板（iOS 里就有「存储到照片」）；不支持时回退到 **blob URL** 下载 |

> 早期版本用 `<a download href="data:...">`，在手机上点了完全没反应：iOS Safari 对 data URL
> 忽略 `download` 属性，App 内置浏览器更是直接屏蔽下载。已改为上面的方案。

### 图片弹窗的视口高度

弹窗必须用 `height: 100dvh`。`position: fixed; inset: 0` 在 iOS Safari 和微信里取的是
**「大视口」**高度，底部那排按钮会被浏览器工具栏盖住，看得见却点不到。除此之外顶部还放了
一个关闭按钮作为兜底，点遮罩空白处也能关。
